# 10단원. 실전 투자 전략: RAG와 AI 활용 (퀀트 실무자 관점)

원본이 개요 수준이므로, 퀀트 실무 파이프라인에 실제로 RAG/LLM을 결합할 때의 구체적 설계 포인트로 재구성한다.

## 1. RAG 시스템 — 퀀트 파이프라인에서의 위치

RAG는 **비정형 데이터(공시, 뉴스, 리서치 보고서)를 정형 팩터로 변환하는 전처리 계층**으로 이해하는 것이 정확하다. 순수 팩터 모델(가격·재무 기반)이 놓치는 정보 — 경영진 톤, 리스크 요인 서술의 변화, 소송·규제 이슈 — 를 구조화하는 역할이다.

```
공시/뉴스 원문 → 청킹(chunking) → 임베딩 → 벡터DB 색인
                                              ↓
쿼리(예: "이 기업의 최근 리스크 요인 변화는?") → 벡터 검색 → LLM 요약/분류 → 팩터화
```

## 2. RAG를 투자 분석에 쓸 때의 구체적 설계

### 공시 자동 분석 → 텍스트 팩터

- DART 사업보고서의 "사업위험" 섹션을 매 분기 임베딩 비교(cosine similarity)해 **서술 변화도(textual novelty)**를 산출 — 변화가 클수록 리스크 요인 변화 가능성
- 실적발표 컨퍼런스콜 녹취록의 톤 분석(긍정/부정 단어 비율)을 **관리자 톤 팩터**로 사용 — 학계에서 Loughran-McDonald 사전 기반 방법이 검증됨

### 과거 유사 사례 검색

- 현재 매크로/업종 상황과 벡터 유사도가 높은 과거 시점을 검색해 유사 사례의 forward return 분포를 참고자료로 제시 — 단, 이는 예측이 아니라 **유사도 기반 시나리오 분석**임을 명확히 해야 함(생존편향·소표본 문제 그대로 적용)

### 실시간 데이터 통합

- 벡터DB에 최신 공시를 지속 색인하되, **팩터 계산에 사용하는 시점은 반드시 공시 발표 이후 체결 가능 시점**으로 정렬(룩어헤드 바이어스 방지는 여기서도 동일하게 핵심)

## 3. HMM 기반 시장 국면 추정 — RAG 파이프라인과 결합 가능한 비지도 ML 기법

"시장이 잔잔한지 불안한지"를 판단하는 문제는, 은닉 마르코프 모델(HMM: Hidden Markov Model)처럼 관측값(수익률, 변동성)으로부터 잠재 상태(국면)의 확률을 추정하는 비지도 학습 기법으로 정량화할 수 있다.

- HMM은 시장을 "저변동성/고변동성" 같은 몇 개의 이산 상태로 가정하고, 상태 간 전이확률과 각 상태에서의 관측값 분포를 데이터로부터 추정한다 — 이동평균 교차 같은 규칙 기반 국면 필터보다 상태 전환 시점을 더 유연하게 포착할 수 있다는 것이 장점
- 실무 적용 시 주의점: 상태 수(2개 vs 3개 이상)를 늘릴수록 in-sample 적합도는 좋아지지만 out-of-sample 안정성은 떨어지는 전형적 과적합 트레이드오프가 있다 — walk-forward로 상태 수와 파라미터 안정성을 검증해야 함
- RAG 파이프라인과의 결합 지점: 가격 기반 HMM 국면 추정치와, 앞서 다룬 텍스트 기반 리스크 팩터(서술 변화도, 관리자 톤)를 함께 입력해 "가격은 아직 반영하지 않았지만 텍스트에서 국면 전환 신호가 먼저 나타나는가"를 검증하는 멀티모달 리서치가 가능하다

## 4. AI 기반 투자 전략 — 실무 아키텍처

| 구성요소 | 역할 | 실무 주의점 |
|---|---|---|
| 퀀트 전략 + LLM 해석 | 팩터 모델의 정량 스코어를 LLM이 자연어로 설명 | LLM이 스코어를 사후적으로 그럴듯하게 "정당화"하는 confabulation 리스크 — 설명이 실제 모델 로직과 일치하는지 검증 필요 |
| 포트폴리오 리스크 자동 진단 | 뉴스/공시 기반 리스크 이벤트를 포트폴리오 종목에 매핑해 알림 | False positive 관리(불필요한 알림 남발) — 임계값을 백테스트로 튜닝 |
| 뉴스 감성 분석 | 감성 점수를 단기 모멘텀 팩터로 활용 | 감성 팩터는 빠르게 알파가 소멸(decay)하는 경향 — 지속성 검증 필수, 다수 시장참여자가 이미 활용 중이라 엣지가 작을 수 있음 |

### XAI(설명가능 AI) → confabulation 리스크의 실무 완화 수단

위 표에서 지적한 LLM confabulation 리스크는, XAI(Explainable AI) 기법을 파이프라인에 결합해 부분적으로 완화할 수 있다.

- 트리 기반 모델(그래디언트 부스팅 등)을 팩터 결합에 쓴다면 SHAP·Feature Importance로 "어떤 팩터가 최종 스코어에 얼마나 기여했는가"를 정량적으로 추출할 수 있다 — 이 수치와 LLM이 자연어로 생성한 설명이 일치하는지 대조하는 것이 confabulation 탐지의 실무적 방법이다
- LLM에게 "왜 이 종목의 스코어가 높은가"를 물어 얻은 자연어 설명은 **그 자체로는 검증되지 않은 가설**이며, 반드시 실제 팩터 기여도(XAI 출력)나 룰 기반 백테스트로 재현 가능한지 대조해야 앞서 강조한 "설명 가능한 재현성"이 확보된다
- 블랙박스 모델(딥러닝 기반 시그널)을 실전 배치하기 전에는, 최소한 사후적으로 결정 경계를 근사 설명할 수 있는 대체 모델(surrogate model)을 함께 두는 것이 리스크 관리 측면에서 권장된다

## 5. 로보어드바이저·투자 인디케이터 개발 — 실전 프로젝트 아키텍처 참고

퀀트 포트폴리오를 실습형으로 개발할 때(로보어드바이저, 자체 투자 인디케이터), 위에서 다룬 요소들이 실제로 어떻게 하나의 파이프라인으로 결합되는지 정리하면 다음과 같다.

1. **데이터 수집층**: 가격·재무(정형) + 공시·뉴스(비정형, RAG 색인) 이원화
2. **팩터/시그널 생성층**: 앞선 문서들에서 다룬 가치·모멘텀·퀄리티 팩터 + HMM 국면 신호 + 텍스트 팩터를 IC 가중으로 결합
3. **포트폴리오 구성층**: 05번 문서의 리스크 패리티·공분산 축소 추정을 적용해 비중 산출
4. **성과 검증층**: 04번 문서의 walk-forward·부트스트랩 검증을 반드시 거친 뒤에만 실전 배치 후보로 승격
5. **모니터링층**: XAI 기반 팩터 기여도 추적 + 리스크 이벤트 알림(위 표)으로 운영 중 이상 신호 감시

로보어드바이저 프로젝트를 "AI가 알아서 추천해준다"는 블랙박스로 설계하지 않고, 위 5개 층 각각을 독립적으로 검증 가능한 모듈로 분리하는 것이 실무 포트폴리오로서의 완성도를 좌우한다.

## 6. 실전 적용 체크리스트 — 정량 기준으로 재구성

1. **데이터 품질 확인**: 벡터DB 색인 데이터의 발표시점(timestamp)이 정확한가 — 정정공시·데이터 벤더 지연을 반영했는가
2. **RAG 인덱스 최신성 유지**: 색인 지연이 시그널 지연으로 이어지지 않는가(예: 공시 발표부터 색인까지 걸리는 시간을 SLA로 관리)
3. **LLM 답변의 출처 검증**: LLM이 생성한 팩터/시그널을 실제 룰 기반 백테스트로 재현 가능한가 — "설명 가능한 재현성"이 없으면 실전 배치 불가
4. **투자 판단은 본인 책임**: 리스크 관리 관점에서는, LLM 기반 시그널에 대해서도 다른 팩터와 동일하게 IC·샤프비율·MDD 기준의 성과 검증을 거쳐야 하며, "AI가 말했다"는 이유로 검증 절차를 생략하면 안 됨
5. **국면 추정 모델의 과적합 관리**: HMM 등 비지도 국면 추정 모델의 상태 수·파라미터를 walk-forward로 검증했는가
6. **XAI 대조 검증**: LLM의 자연어 설명이 실제 팩터 기여도(SHAP 등)와 일치하는지 주기적으로 대조했는가

## 실무 결론

RAG/LLM은 퀀트 파이프라인에서 **비정형 데이터를 정형 팩터로 전환하는 도구**로 취급하는 것이 가장 안전하다. LLM의 출력을 최종 매매 신호로 직접 쓰기보다, 기존 팩터 프레임워크(IC 검증, walk-forward, 거래비용 반영)에 새로운 팩터 후보로 편입해 동일한 엄격도로 검증하는 것이 실무 표준이다.
