# 주식 4 (퀀트 실무자 관점)

이 문서는 원본이 이미 퀀트 실무 자료에 가깝다. 핵심 보강 포인트만 짚는다.

## "3일 연속 하락 후 반등" 가설 — 실무 검증 절차 보강

원본의 워크플로(가설→조건 검색→반등 측정)에 실무에서 반드시 추가해야 할 단계:

1. **기저율(base rate) 비교**: 3일 연속 하락 조건과 무관하게 임의의 날 다음날 상승 확률과 비교해야 진짜 엣지인지 판단 가능
2. **통계적 유의성**: 80~120회 표본이면 이항검정으로 승률이 50%(혹은 기저율)와 유의하게 다른지 검정 (표본이 적으면 신뢰구간이 넓음에 유의)
3. **레짐 의존성**: 상승장/하락장/횡보장 구간별로 나눠 재검증 — 한 레짐에서만 작동하는 패턴은 실전에서 실패할 가능성이 높음
4. **체결가정 명확화**: "장 마감 후 매수 신호 → 익일 시가 체결"인지 "당일 종가 체결"인지에 따라 결과가 달라짐. 미래 정보 사용(look-ahead) 여부를 반드시 점검

## 생존편향·과최적화·거래비용 — 세 가지 함정의 정량적 대응

원본이 잘 짚은 3대 함정에 대한 실무 대응법을 추가한다.

| 함정 | 정량적 대응 |
|---|---|
| 과적합 | Walk-forward validation, 파라미터 수를 최소화(자유도 대비 표본 수 확인), in-sample/out-of-sample 성과 격차 모니터링 |
| 생존편향 | 상장폐지·관리종목 이력을 포함한 point-in-time 유니버스 사용 (현재 상장 종목만 쓰면 안 됨) |
| 비용 미반영 | 호가스프레드, 시장충격비용(market impact), 거래세, 슬리피지를 수익률 계산에 반드시 포함 — 특히 저유동성 종목은 이론 수익률과 실현 수익률의 괴리가 큼 |

## LEAN 프레임워크 — 실무 아키텍처와의 대응

LEAN의 5단계 모듈(Universe Selection → Alpha → Portfolio Construction → Execution → Risk Management)은 기관 퀀트 파이프라인의 표준 구조와 정확히 일치한다.

- **Universe Selection**: 유동성 필터(일평균 거래대금), 시가총액 필터를 먼저 걸어 생존편향·유동성 리스크를 통제
- **Alpha Creation**: 여러 시그널을 앙상블할 때는 단순 합산보다 IC 가중 결합이 표준
- **Portfolio Construction**: 리스크 패리티, 평균-분산 최적화 등 — 단일 시그널 랭킹을 그대로 비중으로 쓰면 집중 리스크가 커짐
- **Execution**: 원본이 강조하듯 신호 발생 시점과 체결 시점의 분리가 필수
- **Risk Management**: 종목당 비중 상한, 포트폴리오 MDD 트리거는 전략과 독립적으로 항상 적용되어야 하는 오버레이

## 레버리지 상품(선물·신용) 백테스트 — 증거금·마진콜·반대매매를 체결 제약으로 모델링

선물·신용거래처럼 레버리지가 내재된 상품을 백테스트할 때는, 현금 매수 전략과 달리 **강제청산 메커니즘 자체가 수익률 경로를 바꾼다.**

- 증거금(개시증거금·유지증거금)은 "계약 보증금" 성격이며, 평가손실로 유지증거금 아래로 떨어지면 마진콜이 발생한다 — 백테스트 엔진은 일별 정산(mark-to-market) 후 증거금 부족분을 시뮬레이션하고, 추가 납입이 없으면 다음 거래일 반대매매(강제청산)를 체결가정에 반영해야 한다
- 반대매매는 보유자의 의사와 무관하게 시장가·시가 근접 가격에 체결되므로, 일반적인 "신호 발생 → 지정가 체결" 가정과 다른 슬리피지 모델을 별도로 둬야 한다 — 특히 급락일에는 반대매매 물량이 몰려 체결가가 이론가보다 크게 불리할 수 있다
- 초보자 원칙으로 흔히 언급되는 "레버리지를 낮게, 증거금 여유를 크게" 같은 규칙은 퀀트 전략에서는 **최대 레버리지 배수를 사전 고정 파라미터로 두고, 이 값을 in-sample에서 튜닝하지 않는 것**으로 구현한다 — 레버리지 배수를 최적화 대상으로 두면 과최적화로 이어지기 쉽다
- 만기·증거금·강제청산 규칙은 상품(주식 신용융자, 선물, 옵션 매도)마다 다르므로, 멀티에셋 백테스트 엔진은 상품별 증거금 규칙을 별도 모듈로 분리해 관리해야 한다

## 노코드 퀀트 플랫폼(젠포트·퀀터스류) vs LEAN — 실무 활용의 경계

젠포트·퀀터스 같은 노코드 플랫폼은 전략을 만들고 검증하는 진입장벽을 낮추지만, 실무 파이프라인에서의 위치는 LEAN과 명확히 다르다.

| 구분 | 노코드 플랫폼 | LEAN(코드 기반) |
|---|---|---|
| 전략 표현력 | 사전 정의된 블록·조건 조합 위주 | 임의의 알고리즘(ML 모델 포함) 구현 가능 |
| 체결 제약 커스터마이징 | 제한적(플랫폼 기본값 의존) | 슬리피지·수수료·증거금 모델을 직접 정의 가능 |
| 재현성·버전관리 | 플랫폼 UI에 종속 | 코드 저장소로 완전한 버전관리·CI 통합 가능 |
| 적합한 용도 | 빠른 가설 스크리닝, 프로토타이핑 | 실전 배치 전 최종 검증, 기관급 리스크 관리 통합 |

실무에서는 노코드 플랫폼으로 대량의 가설을 빠르게 걸러낸 뒤, 통과한 소수 전략만 LEAN 같은 코드 기반 엔진으로 옮겨 위 체크리스트(생존편향, 거래비용, walk-forward)를 완전한 형태로 재검증하는 **2단계 워크플로**가 합리적이다.

## 가상자산 백테스트 — 전통 주식 백테스트와 다른 지점

가상자산을 유니버스에 포함할 경우, 위에서 다룬 표준 체크리스트에 더해 다음을 추가로 반영해야 한다.

- **24/7 시장**: 거래소가 휴장하지 않으므로 "일봉 종가" 기준 리밸런싱 가정이 전통 주식과 다른 갭 리스크 프로파일을 만든다 — 주말·심야 유동성 저하 구간의 슬리피지를 별도로 모델링
- **거래소 리스크**: 상장폐지·거래소 자체 파산(카운터파티 리스크)은 개별 종목 상장폐지보다 훨씬 빈번하고 손실 규모가 큰 이벤트이므로, point-in-time 유니버스 구성 시 거래소 단위 생존편향도 함께 통제해야 한다
- **유동성 파편화**: 동일 코인이 여러 거래소에서 다른 가격에 거래되므로, 백테스트에 사용할 가격 소스(특정 거래소 vs 거래량가중 평균)를 명시하고 실제 체결 가능한 유동성 범위 내에서 포지션 크기를 제한해야 한다
- **규제·과세 변화**: 국가별 규제 변화가 비정기적이고 사전 예측이 어려운 구조적 리스크이므로, 백테스트 기간 중 규제 이벤트 구간을 별도 표시해 성과를 과신하지 않도록 관리한다

## 여러 기간 검증(out-of-sample) — 실무에서의 표준 분할

원본이 제시한 기간 분할(급락기/추세전환기/회복기)은 좋은 출발점이나, 실무에서는 다음을 추가한다.

- **롤링 윈도우 검증**: 고정된 3~4개 구간이 아니라, 예를 들어 3년 학습→1년 검증을 매년 롤링하며 파라미터 안정성을 확인
- **몬테카를로 재표본(bootstrap)**: 거래 순서를 임의 재배열해 MDD·샤프비율의 신뢰구간을 추정 — 단일 경로 결과에만 의존하지 않음
- **파라미터 안정성 지도(heatmap)**: 파라미터를 소폭 변화시켰을 때 성과가 절벽처럼 무너지면 과적합 신호

## 실무 체크리스트

1. 신호 표본 수 대비 통계적 유의성을 검정했는가
2. Point-in-time 유니버스(상장폐지 종목 포함)를 사용했는가
3. 거래비용·슬리피지를 현실적으로 반영했는가
4. 파라미터를 여러 독립 구간에서 walk-forward로 검증했는가
5. 신호 발생과 체결 시점을 명확히 분리해 룩어헤드 바이어스를 제거했는가
6. 레버리지 상품의 경우 증거금·마진콜·반대매매를 체결 제약으로 시뮬레이션했는가
7. 가상자산 포함 시 24/7 시장·거래소 카운터파티 리스크·유동성 파편화를 별도로 반영했는가
